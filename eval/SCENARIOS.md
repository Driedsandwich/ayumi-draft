# 審査・評価の台本

すべて合成の架空例です。cases.json の expected は人手で書いた正解の期間・7欄の表です。mock の解析関数から生成していません。採点は完全一致（nullも1欄）。期間は始めと終わりの組、欄は start/end/care/hospital/daily/work/treatment。欠落・余分な行も分母に含めます。合格基準は期間・欄100%、不足0、余分な期間0、引用にない値・正解表にない日付0、想定確認事項の検出100%。本物も同じ基準で実行し、低い結果を隠しません。

1. ページを開き、鍵なし体験のまま「受診しなかった期間がある」を選ぶ。
2. 送る内容を確認 → 整理。日付の不足などの聞き返しが最大5件で出る。
3. 日付または生活の回答を入力 → 確認 → 再整理。該当する欄だけが変わり、他の期間が残る。
4. 「今は分からない」で1件を残す。下書きに残った確認事項が表示される。
5. 印刷を開く。期間の表・確認事項・相談時の要点・本人メモがあり、操作ボタンがない。
6. リロードして戻る。入力・回答途中・下書き・保留が復元される。
7. 「保存した内容を消す」。リロードしても健康情報は戻らない。
8. 残りの見本（就労と離職、初診日不明）でも繰り返す。学年から年を勝手に補わない。
9. 新規入力：`2023年4月1日から現在まで、ふたば医院に通院している。食事は家族が作る。仕事は休んでいる。` を使う。見本の医療機関名を返さず、新規の文と引用で動く。
10. 本番AI設定後、整理の方法を「AI」に変える。送信先と内容、同意のチェックを確認。上記と同じ流れを試す。
11. 通信を失敗させる。エラーを表示し、前の下書きと入力を失わない。中止ボタンを押した後に遅い応答で内容が復活しない。

自動評価：`npm run eval` / 環境変数を設定して `npm run eval:real`。本物のスクリプトはデモ用の合成文だけを送信し、結果JSONに原文やAI出力を保存しません。最大28回（14件×最大2回）。mockはAI呼び出し0回。ブラウザー試験：`npm run verify:ui`。

数値の限界：完全一致は別の正しい抽出や長い引用も不一致として厳しく採点します。捏造検査は余分な行・日付・引用の実在を検査し、意味の捏造を完全に検証するものではありません。正解表と実際の出力の人手確認も必要です。
