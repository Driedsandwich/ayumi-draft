# あゆみの下書き

話すように書いた経過を整理して、障害年金の「病歴・就労状況等申立書」の下書きを作る Web アプリです。

- 公開デモ：<https://ayumi-draft.vercel.app>（2026-11-06 時点で実 AI に接続した構成）
- 東京AIハッカソン 2026 のために作りました。
- AI の鍵（API キー）がなくても、手元では見本の応答（mock）で最後まで動きます。動かし方は下の節にあります。
- ライセンス：MIT（[LICENSE](LICENSE)）。`docs/form.pdf`・`docs/form-1.png`・`docs/form-2.png` は日本年金機構の様式の確認用の写しで、提供元の条件に従います（MIT の対象外）。

名前の候補：**あゆみの下書き**（採用）／**ことばから申立書**／**経過のしおり**。

障害年金の「病歴・就労状況等申立書」を準備するための Web アプリです。話すように書いた経過を期間と欄に整理し、引用・日付・空白・受診先をコードで確かめます。本人が短い回答を足して、確認事項つきの下書きを印刷できます。等級や受給の見込みは判定しません。

学生ハッカソン一次審査向けの試作。日本語・スマートフォン対応。鍵なしでも新規入力から最後まで動きます。**実AI評価は未実施**です。ローカルの模擬応答試験は実AI評価として数えていません。公開デモは冒頭の URL にあります。

## すぐ動かす

Node.js 22.12以上と npm を使います。

```sh
npm ci
npm run dev
```

表示されたローカルURLを開きます。「見本で試す」で架空の経過が入ります。「内容を確認して進む」→「この内容で整理する（AI は使いません）」→聞き返し→「下書きを見る」→印刷と進めます。初診日が分からなくても、質問は後に残せます。最初から最後まで AI を使わず、端末内で試せます。別の見本も入力欄の下から選べます。

すべての段の冒頭に3段の道案内と現在地を表示します。料金の説明は最初の画面と送信ボタンの近くにあります。ログイン・支払い情報の入力欄はありません。最後の「最初に戻る」は内容を残して戻り、「自分の入力で試す」は見本とその回答を空欄に戻します（見本を使わずに書き始めた内容は保持します）。

```sh
npm test
npm run build
npm run eval
```

`build` は TypeScript 検査、Vite の静的出力、esbuild の API バンドルを一度に作ります。出力は `dist/` と `api/analyze.js` です。`npm run preview` は静的画面の確認用で、鍵なし体験が使えます。本物のAPIは `npm run dev` または Vercel 上で動かします。

ブラウザー試験：

```sh
npx playwright install chromium
npm run verify:ui
```

既存の Chromium を使う場合は `PLAYWRIGHT_CHROMIUM_EXECUTABLE` にその実行ファイルのパスを設定できます。npm の optional peer 解決の不具合を避けるため `.npmrc` で `legacy-peer-deps=true` を指定し、依存を lockfile に固定しています。

## 本物のAIにつなぐ

provider の形を OpenAI互換の Chat Completions に絞っています。鍵はサーバー環境変数だけに置きます。`.env.example` は作成していません。鍵の値をソース、README、Git、画面に書かないでください。ブラウザー向けの `VITE_` 変数に鍵を設定しないでください。

| 環境変数            | 用途                                                                               |
| ------------------- | ---------------------------------------------------------------------------------- |
| `AI_PROVIDER`       | 未設定または `mock` は鍵なし。実AIは `openai`                                      |
| `AI_BASE_URL`       | 管理者が選ぶ HTTPS の OpenAI互換ベースURL。末尾に `/chat/completions` を付けて呼ぶ |
| `AI_MODEL`          | その接続先で使えるモデル名                                                         |
| `AI_API_KEY`        | その接続先の鍵。値は記載しない                                                     |
| `RATE_LIMIT_SECRET` | 32文字以上のランダムな秘密。署名Cookie・IPのハッシュに使う。実AIでは必須           |
| `RATE_LIMIT_MAX`    | 1分の署名Cookie上限。既定8回、最大30回                                             |
| `IP_RATE_MAX`       | 関数実体ごとの同一接続10分の上限。既定60回、最大600回                              |

JSON mode (`response_format: json_object`) と `max_tokens` に対応する接続先が必要です。モデル固有のAPI互換性は実機未確認です。鍵が欠けた本番設定を、黙ってmockに切り替えることはしません。

実AIの設定後は「自分の経過を書く」または最後の「自分の入力で試す」から、AI で整理する方法を選んで入力を始められます。接続通知だけで整理方法が切り替わることはありません。画面下部の「設定と保存について」の「整理の方法」でも切り替えられます。「AI で読む（数秒かかります）」が実際に AI を呼ぶボタンです。送信先のホスト、送る経過または回答、その取り扱いを確認して同意すると送信します。追加情報の初診日・発病日・傷病名・現在の医療機関、および裏面の本人メモは、別入力分をAIへ送りません。経過本文にそれらを書いた場合は本文に含まれて送信されます。

`npm run eval:real` は同じ14件の合成文を本物の接続先へ送り、最大28回の呼び出しで評価します。環境がない場合は終了コード2で「未確認」を返し、成功の結果ファイルを偽造しません。

## Vercelへの配置

このフォルダが独立した新しいリポジトリです。新しいGitリモートへ push し、このフォルダをプロジェクトのルートとして Vercel に登録します。フレームワークはVite、Node.jsは22系、ビルドは `npm run build`、出力は `dist`。`vercel.json` を同梱しています。APIは esbuild で生成する **`api/analyze.js` 1本**です。

環境変数なしなら公開先も鍵なしで利用できます。実AIを使う場合は Vercel のサーバー環境変数を設定して再デプロイします。デプロイ後は `/api/analyze` のGETでproviderと送信先のホストを確認し、[審査台本](eval/SCENARIOS.md) を公開URLで一巡してください。公開デモの上での審査台本の通し確認と、運用基盤の保持条件は未確認です。

## AIとコードの分担

| 担当         | 実装すること                                                                                                                     | 実装場所                                       |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| AI           | 自由文から出来事を抽出。期間の始め・終わり、受診の有無、医療機関名、日常生活、就労、治療・未受診理由をJSON化。項目ごとに原文引用 | `server/providers.ts`                          |
| AI           | 聞き返しへの回答を、指定された期間・指定欄だけの更新JSONにする                                                                   | 同上                                           |
| コード       | JSON型・上限・期間の原文・項目の引用・値が引用に含まれること・受診の明白な矛盾を照合。形や引用が不正なら1回だけ再抽出            | `src/core/schema.ts`, `pipeline.ts`, `care.ts` |
| コード       | 明示された和暦・西暦の年月日を解釈。年や年月だけの精度を保持。学年・相対日付から年を補わない                                     | `src/core/dates.ts`                            |
| コード       | 日付の前後、未来日、空白、重なり、医療機関の不足、未受診と医療機関の矛盾、初診日との食い違い、発病から現在の連続性を確認         | `src/core/rules.ts`                            |
| コード       | 長い期間の3〜5年の区切り候補を計算。日付不明なら具体的な候補日を作らない。質問生成は最大5件ずつ（D1画面では1件ずつ表示）                                      | 同上・`dates.ts`                               |
| コード       | 回答を指定欄だけに反映し再検査。他の期間を勝手に書き換えない                                                                     | `applyPatches`, `App.tsx`                      |
| 本人         | 不足に回答。原文を確認し、必要なら期間を追記・削除。裏面の生活の選択肢は本人が直接選ぶ                                           | `src/ui/`                                      |
| 本人・専門家 | 医学的内容、初診日の証明、記載簡素化の適用、正式用紙への転記、提出前の確認                                                       | アプリの自動判定の対象外                       |

AIの値は抽出的です。読みやすい言い換えをAIに自由生成させません。日付がそろった期間はコードが並べ直します。一部の日付が不明な場合は、順序を推測せず入力順に残して確認事項を表示します。5年を超える期間の分割は**未確定の候補**として提示し、勝手に新しい経過を作りません。転院や受診中断を同じ行に含むときは、本人に分けた経過を追記してもらい、不要になった元の行を削除できます。

鍵なし版は一般の文に対する決定的な簡易解析で、見本IDや評価正解表を参照しません。日付・受診語・医療機関名・生活や仕事の語を抽出します。複雑な文章の意味理解は本物のAIと同等ではありません。引用の実在は、意味の対応・本人の記憶の真偽・医学的正確性を証明しません。引用の全文を画面で開け、印刷の表にも元の経過を残します。

**公式ルールとアプリ独自の検査を区別**：日付の逆転・未来日・引用の不一致などはコード上の整合検査です。月までしか分からない境界は重なりの可能性として出し、補完しません。同日受診や同時通院は誤りと断定しません。初診日より前の受診は、同じ病気なのか、記憶や記録が違うのかを尋ねます。初診日を確定したり、初診日から障害認定日を自動計算したりしません。

生来性の知的障害や20歳前の一定の初診日証明に伴う記載簡素化は、自動適用しません。長期の分割を絶対条件として押しつけず「専門家と確認」と表示します。裏面のどの欄が必要かも自動判断しません。

## 保存と通信

- 経過・回答途中・下書き・保留・裏面の本人メモは、このブラウザーの `localStorage` に保存。再読込で戻れ、削除ボタンで消せます。共用端末では終わったら消してください。アプリ独自の暗号化はありません。
- 鍵なし解析は端末内。入力・下書きを送信しません。起動時のAPI設定取得には健康情報を含めません。
- 実AIでは入力を関数内で一時処理し、AI提供元へ送ります。入力・応答をDBやファイルへ保存せず、サーバーログへも出しません。エラーにAIの返答本文を含めません。HTTP応答は `no-store`。
- プロバイダー／ホスティングの保持条件はアプリの保存方針とは別です。公開試作では架空の経過で試す案内を送信前に表示します。匿名化が完全であるとは主張しません。
- 1回の整理は最大2回のAI呼び出し。JSON・引用不正時だけ1回取り直します。通信エラーの自動再送はありません。関数内全体46秒、ブラウザー52秒、Vercel関数60秒の上限。
- 回数制限は署名Cookieと、ハッシュ化した接続元ごとの関数メモリーの回数です。病歴はカウンターに含めません。Cookie削除・複数インスタンス・再起動をまたぐ厳密な課金上限ではありません。
- 外部フォント・解析タグ・広告・録音・画像アップロードはありません。

## 構成と範囲

- `src/core/`：JSONの契約・抽出値と引用の照合・日付・ルール・mock・出典
- `src/ui/`：入力、送信前確認、聞き返し、期間カード、裏面メモ、出典。見た目の差し替えができるよう分離
- `src/client/`：端末内保存と復元
- `server/`：providerとHTTP。`api/` はその単一バンドル
- `tests/`, `e2e/`：単体・API・ブラウザー試験
- `eval/`：合成14件の手作り正解表、同じ採点でmock／本物を回す評価器
- `docs/`：試験結果、画面画像、架空例の印刷PDF、公式様式の確認資料

一つの病気の経過を整理する下書き支援に絞っています。診断、等級・受給見込み、初診日の法的な確定、障害認定日・簡素化の自動判定は対象外です。複数の傷病は公式の案内に従って用紙を分けます。この試作には複数案件の切替機能がないため、印刷して端末の内容を消してから次の案件を扱います。

**未実装**：公式PDFの欄への自動書込み・電子申請・録音／音声認識・暗号化した端末保存・厳密な分散課金上限。音声認識済みの文の貼り付けとブラウザーの印刷／PDF保存は実装済みです。端末間の同期・アカウントはありません。

**未確認**：本物のAIの出力品質・接続先固有の互換性、Vercel公開URLでの動作、Safari／実機スクリーンリーダー、制度や医療の専門家による監修。本物の運用前に確認が必要です。

この取り組みが狙うのは、社会保障の入口で本人の経過を文章にする負担です。「語りを整理する部分」と「説明できる決まりを確かめる部分」を分け、本人から支援者・年金事務所へ確認事項ごと渡せる形にします。他制度への対応は将来の展開で、この版では実装していません。

Vite＋React＋TypeScript、providerの分離、Vercel関数1本のesbuild生成、mock、回数制限、vitest、評価台本という構造は、別のアプリの構成を参考にしました。そのアプリの題材の文・見本・画像・OCRは転用していません。


## D1「時間をたどる」の画面

[D1の仕様](DESIGN.md)に合わせ、期間ナビ、期間表と本人の言葉、確認一覧を配置しています。PCでは左160px・中央可変・右300px（列間24px）、狭い画面では縦に並びます。初回の「見本で試す」は1例目をその場で入力します。入力欄の下には、架空の3例を選ぶボタンもあります。

期間の一覧で選び「経過を書く」で、その期間の生活・仕事・治療の欄を補足できます。経過全体の整理は「経過全体を見る」、新しい期間の追記は下書きの「抜けている期間を追記する」から行います。空白の表示は既存のルールが返した確認事項に基づき、受診の有無を推測しません。

「保存して休む」では保存状態を確認できます。選択中の期間と確認中の位置も同じ端末に保存します（補助キー `ayumi-draft-navigation-v1`、既存の経過保存形式は変更なし）。設定の削除操作で両方を初期化します。

追加の画面確認・撮影は、`npm run dev -- --port 4179` を起動した状態で `node scripts/verify-design.mjs docs/d1` を実行します。既存のPlaywrightのみ使用し、390px／1280pxの入力・確認・下書き・初回画面を撮影します。必要なら `PLAYWRIGHT_CHROMIUM_EXECUTABLE` でChromiumを指定してください。


## 初めての人向けの導線確認

`npm run dev -- --port 4179` を起動し、`node scripts/verify-onboarding.mjs docs/onboarding` で、390px／1280px の初回・入力・確認・下書き・AI送信確認を撮影できます。最初の表示範囲の料金説明、見本のAI呼び出し0回、遅い接続通知、戻る操作、自分の入力への切り替えを確認します。AIの接続通知はブラウザー内の模擬応答で、外部へは送信しません。既存の試験・評価の内容は変えていません。
